> 目标：让每章笔记「读完能做题」——**应用导向**：以算法本身和 LeetCode 实战为主线，CLRS 原书只作参考，用于核对概念与复杂度的正确性。文字讲直觉、图展示过程、数学符号能省则省。
> 本文件是所有章节的统一准则；文末附第 6、13 章已执行的决策，作为后续章节的范例（注：第 6 章改于旧准则时期，其「与原书逐节对应」的要求已不再强制）。
>
> **触发方式**：用户说「优化 / 审阅 / 生成第 N 章」→ 按本文件执行：Step 0 提原书 → Step 1–5 → 参照文末两个范例。
> **若该章尚无旧笔记**（如第 26–35 章）：Step 1/2 改为「按第四节骨架直接从原书取材撰写」，其余步骤不变；产出文件命名为 `ChapterNN_章名_深度版.md`。
> **最终关卡**（写完后必做）：① 用脚本把笔记里的 Java/Python 代码块**原样抽出**编译运行 + 随机对拍；② 用 `mermaid.parse`（node + mermaid 包）验证全部 mermaid 块可解析，并审计配色/`color:#1f1f1f`/linkStyle 下标。

## 一、内容准则（适用于所有章节）

### 1. 正确性（CLRS 仅作参考）
- 概念、复杂度、伪代码逻辑要**正确**——拿不准时翻 CLRS 核对，但**不要求章节结构与原书一一对应**。
- **核对方法**：第四版 PDF 在 `/Users/zy/Downloads/IntroductiontoAlgorithms4th.pdf`；用 `pdftotext -f <起> -l <止> <pdf> out.txt` 提取（**PDF 页 = 书页 + 22**），通读原书对应章节后再动笔。伪代码签名、图例、习题编号一律以**第四版**为准（第三版编号不同：如叶子下标 6.1-8 ≠ 第三版 6.1-7；RB-DELETE 的 `y ≠ z.right` ≠ 第三版 `y.p == z`）。
- 章节组织以「这个技术解决什么实际问题、LeetCode 哪些题用它」为主线，不强求覆盖原书每一节。
- 术语规范化，区分易混概念：
  - **下沉 / 下滤 sift-down**（MAX-HEAPIFY、EXTRACT-MAX）
  - **上浮 / 上滤 swim**（INCREASE-KEY、INSERT）
- 数学证明的变量定义清晰，**高度 h ≠ 深度 d**，方向不能写反。
- 跨章内容不串台：高级结构只在「它所属的章节」展开（B 树→第 18 章、不相交集合→第 19 章；斐波那契堆 / van Emde Boas 树第四版已删章，不要写）。

### 1.5 数学克制（新）
- **删掉归纳证明、积分、ε-δ 式推导**——笔记不是教材。
- 递归式只保留「`T(n) = 2T(n/2) + Θ(n)` → `Θ(n log n)`」的**速查形式**；允许一句话直觉（「每层 n，共 log n 层」）。
- 主定理只给**三情况对照表**（每层代价递增→看叶子 / 每层相同→乘层数 / 递减→看根），不给证明、不提正则条件。
- 渐进记号（Θ/O/Ω）保留——它是做题讨论的通用语言；但取整符号、引理编号、定理编号一律省略。

### 2. 无废话
- **删除「纯思维导图」**：`A→B/C/D, B→B1/B2` 这类把文字 bullet 转成图的，信息量为 0。**例外**：章末「要点回顾」可保留**一张**紧凑总览图（第 6、13 章先例）。
- **删除跑题内容**：与本章核心无关的算法（如堆章节里的单调队列、MinStack）。
- **删除「答案无对应题目」的伪习题**。
- **不重复**：同一函数不要给 5 个版本（递归/迭代/原地/对象/Python 各一份）。

### 3. 易懂
- 每章开篇一段「定位」：这章解决什么问题、为什么重要、与前后章节的关系。
- 讲解顺序固定：**直觉（大白话）→ 示意图 → 代码 → 复杂度结论**。
- **多用 Mermaid 画「算法示意图」**（过程演变、递归树、指针移动、分区），少用抽象关系图；纯文字 bullet 能讲清的就不画。
- 每个主题尽量标注 **LeetCode 题号**（如 704 二分查找），方便读者直接去练。

### 4. 结构统一（每章骨架）
1. 开篇定位
2. 核心思想（大白话 + 一张总览图）
3. 各算法 / 操作（逐个：直觉 → 示意图 → 代码 → 复杂度结论 → LeetCode 标注）
4. 代码实现（Java + Python，索引约定统一）
5. 复杂度 / 递归式速查表 + 易混点对比
6. LeetCode 题单（与本章强相关，标注难度与考点）

## 二、Mermaid 图准则（遵循 mermaid-reference skill）

### 配色（Material 200 色阶，黑白背景通用）
| 用途 | fill | stroke | 文字 |
|------|------|--------|------|
| 起点 / 输入 | #FFE082 浅黄 | #F9A825 | #1f1f1f |
| 判断 / 处理 | #80DEEA 浅青 | #0097A7 | #1f1f1f |
| 成功 / 输出 | #A5D6A7 浅绿 | #388E3C | #1f1f1f |
| 错误 / 高亮 | #EF9A9A 浅红 | #C62828 | #1f1f1f |
| 重复 / 关键 | #CE93D8 浅紫 | #7B1FA2 | #1f1f1f |
| 普通节点 | #90CAF9 浅蓝 | #1976D2 | #1f1f1f |

- **每个节点必须带 `color:#1f1f1f`**（否则深色主题下文字不可见）。
- 用 `classDef` 批量定义、`class n1,n2 名字` 批量套用，避免重复 style。
- subgraph 用 50 色阶极浅底（如 `#E3F2FD`）+ `color:#1f1f1f`，**容器淡、内容浓**。

### 语法红线
- 标签含 `()` `[]` `?` `=` `/` `:` 等 → 双引号包裹：`A["f(x)"]`。
- 长标签（>10 字符）→ `<br/>` 手动换行（中文不会自动断行）。
- 节点 ID 字母开头（`n1`、`a2`），不用纯数字。
- **subgraph 标题单行、不加 `<br/>`**，含特殊字符则 `subgraph S1["..."]`。
- 对比型图（A vs B）→ 并排大节点 + `~~~`，**不用「subgraph 套单节点」**。
- mermaid 块**绝不放在引用块 `>` 内**。
- 虚线带标签 → `A -.->|"label"| B`；实线 → `A -->|"label"| B`。
- 节点标签里别用半角 `|`（会冲突边标签），改用全角 `｜` 或文字。

### 取舍（图 vs 表）
- **语义着色例外**：红黑树等「颜色即语义」的图，黑节点允许深底白字（`fill:#37474F,stroke:#000,color:#fff`），并在第一张图下注明全章图例；其余节点仍按上方配色表。
- **变换类图**（旋转、fixup 各 Case）→ 「前 → 后」双 subgraph 对照（变换前浅蓝底 `#E3F2FD`、变换后浅绿底 `#E8F5E9`），只画关键节点，子树用占位或文字略去。
- **算法示意图**（树结构、状态演变、流程）→ 用 mermaid。
- **数组快照、数学公式、复杂度对比** → 用 markdown 表格（更清晰、不易出错）。
- **关系总览** → 能一句话说清就别画图。
- **数组演变 trace → 用「一个元素一列」的网格表**：每个数组位置单独占一列，逐行展示演变；可用 `**加粗**` 标记本轮变动的格子或已排序区。**绝不要**把多个数字塞进一个单元格、用 `&nbsp;` 撑间距——渲染极丑。
- **多状态 / 多情况的演变图（≥3 个并列子图）→ 拆成多个独立 mermaid 块、由 markdown 纵向堆叠**，不要塞进一个块靠 dagre 自动排版（会被摆成 2×2 或横排，视觉效果差且不可控）。插入示例的 a/b/c/d、删除修复的 4 种 Case 都用「独立块 + 之间一句文字衔接」的竖排。

## 三、代码准则
- **伪代码**：贴 CLRS 1-indexed 风格（保留原书原味）。
- **可运行代码**：Java + Python，统一 **0-indexed**（实战惯例）。
- 开头一句话说清 1-indexed ↔ 0-indexed 换算：
  `left = 2i+1，right = 2i+2，parent = (i-1)/2`。
- 代码必须**可编译 / 可运行**（不能引用未定义的类），且**写完后实际跑一遍**：`javac && java`、`python3` 直接执行。
- 复杂结构（堆、红黑树）用「**随机对拍 + 性质自检**」验证：与 `TreeSet` / `set` 对照随机增删结果，每步校验结构性质；正文引用的原书习题答案（最终树形、trace）也用实现跑一遍核对再落笔。
- **去重**：同一操作只给一个干净版本。
